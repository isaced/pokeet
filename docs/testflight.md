# TestFlight from Xcode Cloud

**Status: external TestFlight only.** No App Store listing yet — no metadata, screenshots or price to keep in sync, and no App Review submission. Everything below is the shipped path for the beta.

## Why Xcode Cloud and not a local archive

The app embeds CPython (`Vendor/`, 53 MB staged) and QuickJS, and the project is generated. Archiving locally works, but every upload then depends on one Mac's certificates, a built `Vendor/` tree and a fresh `xcodegen` run. Xcode Cloud signs with certificates it manages, so a release is a git push and 20 minutes — and a stranger cloning the repo can reproduce it.

The cost is one thing to remember: **Xcode Cloud can only attach a workflow to a project that exists in the repository**, which is why `Pokeet.xcodeproj` is force-added despite being generated. `ci_scripts/ci_post_clone.sh` regenerates it (and stages `Vendor/`) before every build, so `project.yml` stays the single source of truth.

## What a build needs

| Piece | Where it comes from |
|---|---|
| `Pokeet.xcodeproj` + shared scheme | committed; regenerated from `project.yml` in `ci_post_clone` |
| `Pokeet/Info.plist` | generated by XcodeGen; committed as well, because the project references it |
| `Vendor/` (Python.xcframework, python-home) | `scripts/fetch-python.sh`, run by `ci_post_clone` |
| Swift packages | resolved from the network; `Package.resolved` is committed inside the project |
| Signing | Xcode Cloud, automatic |
| Build number | Xcode Cloud, "Manage build numbers automatically" |
| Marketing version | `CFBundleShortVersionString` in `project.yml` |

No secrets are needed at build time: keys live in the Keychain, entered by the user at runtime.

## The workflow

One workflow, `TestFlight`:

- **Start condition**: tag changes matching `v*`. A branch trigger would upload a build on every push and burn compute minutes; a tag is the release act.
- **Environment**: latest Xcode with iOS 18 support.
- **Actions**: Build → Test (`Pokeet` scheme, `PokeetTests`) → Archive (Release) → TestFlight (Internal Testing), plus External Testing once a group exists.
- **Post-action**: notify testers, so the group does not sit on an unannounced build.

Rolling a release:

```bash
# bump the version in project.yml, regenerate, commit, tag
git tag v0.1.0-beta.2 && git push origin v0.1.0-beta.2
asc xcode-cloud run --app APP_ID --workflow TestFlight --branch main --wait
asc builds wait --app APP_ID --latest
```

## External testing

Internal testers need only an App Store Connect role; external testers need **Beta App Review** on the first build of each version, which is where releases get stuck:

- Test Information must be complete: beta description, feedback email, contact name and phone, privacy policy URL.
- `ITSAppUsesNonExemptEncryption` is already `false` in `project.yml`, so the export-compliance question does not block processing.
- The reviewers cannot use the app without a model key. App Review notes carry a throwaway key that is revoked after the beta; it must never be committed or shipped in the binary.

### The notes reviewers get

Written in App Store Connect, not in the repository, because step 2 is the key:

1. Settings → Model → Manage providers → Add provider.
2. API format `OpenAI Responses`, Base URL `https://opencode.ai/zen/go/v1`, the beta key.
3. Fetch models from provider → `opencode-go/deepseek-v4.1-flash`.
4. Projects → New project → create (no remote needed).
5. Ask for `hello.py`, approve the diff, open Changes, commit.

Plus the 2.5.2 paragraph: interpreters are in the binary, nothing is downloaded, writes are confined to the app's Documents workspace and surface as diffs.

```bash
asc testflight groups list --app APP_ID
asc builds add-groups --app APP_ID --latest --group "External" --submit --confirm
```

## Review risk to keep ready

`docs/scripts.md` argues the interpreter case for guideline 2.5.2 (interpreters compiled into the app, no downloaded executable code). Reuse it verbatim in App Review notes: the agent may write scripts, but the runtime is bundled, and every script is confined to the app's own Documents workspace.
