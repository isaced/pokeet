# Sandboxed scripts (`run_script`)

The agent can read, search, edit and diff code. `run_script` closes the loop: it lets the agent check what it just did — compute a value, test a regex, parse a config file, or run a handful of assertions.

It is deliberately **not** a shell:

| Capability | Available? |
|---|---|
| Read repository files | yes, through `fs` |
| Propose file changes | yes, buffered and reviewed as diffs |
| Write files directly | no |
| Network | no |
| Shell, `npm`, `pip`, compilers | no |
| Delete or rename files | no |

That boundary is the point. Real test suites need a computer; a phone should not pretend otherwise. `run_script` handles what reading code cannot settle, and a remote runner is the path for everything else.

## Design decisions

### Runtime: QuickJS, not JavaScriptCore

JavaScriptCore ships with iOS, but its public API has **no execution-time limit and no memory limit** — `JSContextGroupSetExecutionTimeLimit` lives in private headers and is App Store risk. The agent loop's timeout (`AgentSession.executeTool`) only stops *waiting*: the runaway thread keeps burning CPU until the app is killed. For code generated by a model, that is not acceptable.

QuickJS-NG (MIT, vendored C) exposes what we need from public API:

- `JS_SetInterruptHandler` — a deadline check that is polled inside the interpreter and aborts the run
- `JS_SetMemoryLimit` — allocation fails instead of jetsam-killing the app
- `JS_SetMaxStackSize` — deep recursion aborts instead of overflowing the native stack

It is an interpreter, so no JIT entitlement is involved, and the interpreter is compiled into the app rather than downloaded, which keeps the feature inside App Store guideline 2.5.2.

Measured on an iPhoneOS arm64 release build:

| | |
|---|---|
| Binary delta | ~2.8 MB (`__text` +1.0 MB) |
| Runtime + context creation | ~1.4 ms |
| Loop throughput (1e6 additions) | ~40 ms |
| Infinite loop aborted at a 500 ms deadline | 500 ms, 8.7k interrupt polls |
| 32 MB allocation bomb | aborted in ~30 ms |

### Filesystem: overlay, never direct writes

Scripts see an `OverlayScriptFileSystem`:

- reads fall through to the workspace (`read_file` limits apply);
- writes are buffered in memory, capped (per file, total, and file count);
- when the run ends, buffered writes are diffed against the pre-run content and returned as ordinary `FileProposal`s.

So `run_script` composes with the existing review UI: Ask mode shows a diff card per changed file, Auto and Bypass apply as usual, and a script that is interrupted mid-run has its buffered writes discarded. The agent cannot use a script to skip review.

Path validation reuses `PathSandbox`: no absolute paths, no `~`, no `..`, no `.git`.

### Output and termination

`ScriptResult` carries `exitCode`, `stdout`, `stderr`, `termination` (`exited`, `threw`, `timedOut`, `outOfMemory`, `cancelled`), `outputTruncated` and duration. Output is hard-capped (default 16 KB total, newline included), and every log line is newline-terminated.

In the app, the trace row for a script collapses to a single status line (`Ran · JavaScript · exit 0 · 12 ms`) and expands to the script source plus the captured output, so a run can be audited without re-reading the conversation. Script rows are serialised rather than batched with `read_file`, because they can touch the overlay.

Cancellation is cooperative in both directions: the caller may cancel the Swift task, which sets a flag the engine's interrupt handler polls, so the interpreter stops instead of being abandoned.

## Sandbox API

Everything is injected by a ~200-line JavaScript prelude that funnels through one C bridge function, `__hostCall(op, argsJSON)`.

```js
console.log / info / debug / warn / error   // stdout (warn/error go to stderr)
print(...)

assert(condition, message)
assert.equal(actual, expected, message)
assert.notEqual(actual, unexpected, message)
assert.deepEqual(actual, expected, message)  // JSON comparison
assert.throws(fn, message)

fs.read(path) / fs.readText(path) / fs.readJSON(path)
fs.write(path, content)            // content: string or JSON-serialisable value
fs.append(path, content)
fs.exists(path)
fs.info(path)                      // { exists, isDirectory, sizeBytes, lineCount, isText }
fs.list(path) / fs.listRecursive(path)
fs.readdir(path)                   // alias for fs.list

path.join / dirname / basename / extname / normalize / resolve / sep

require('./relative/module.js')    // CommonJS, relative paths only
require('./data.json')

process.argv / process.env / process.cwd() / process.exit(code)
```

`require` supports relative files, `.js`, `.json` and `index.js`, with a module cache. Package names fail with an explicit "no node_modules" message so the model stops trying.

Not provided: `fetch`, `XMLHttpRequest`, `WebSocket`, timers, `node:*` modules.

## Limits

`ScriptLimits` (all clamped, so a model cannot ask for more):

| Limit | Default | Range |
|---|---|---|
| Wall clock | 15 s | 0.5–60 s |
| Heap | 64 MB | 4–256 MB |
| Stack | 512 KB | 128 KB–4 MB |
| Captured output | 16 KB | 1–64 KB |
| Read per file | 512 KB | 1 KB–2 MB |
| Write per file | 200 KB | up to `WorkspaceLimits.maxWriteBytes` |
| Files touched | 20 | 1–100 |

`timeout_ms` is capped at 55 s so the engine interrupts before the agent loop's 60 s tool timeout fires.

## Modes

| Mode | `run_script` |
|---|---|
| Plan | disabled (read-only investigation) |
| Ask | enabled; script writes arrive as diff cards |
| Auto | enabled; safe changes apply automatically |
| Bypass | enabled; everything applies |

`run_script` is not classified as a read-only tool, so runs are serialised rather than batched with `read_file`.

## Layout

```
Packages/PokeetCore/Sources/PokeetCore/Scripting/
  ScriptRuntime.swift        // ScriptRuntime protocol, ScriptLimits, ScriptResult, ScriptRuntimes
  ScriptFileSystem.swift     // protocol + OverlayScriptFileSystem
Packages/PokeetCore/Sources/PokeetCore/Tools/RunScriptTool.swift
Packages/PokeetScripting/Sources/CQuickJS/       // vendored quickjs-ng + pokeet_host.c
Packages/PokeetScripting/Sources/PokeetScripting/
  QuickJSRuntime.swift       // C bridge, limits, termination classification
  JavaScriptPrelude.swift    // sandbox API
```

The kernel stays dependency-free: `PokeetCore` knows only the `ScriptRuntime` protocol, and the app injects `ScriptRuntimes([QuickJSRuntime()])` through `AgentSession(scripting:)`.

## Adding a runtime

Implement `ScriptRuntime` (async `run(_:files:)`) and register it. Rules:

1. Enforce every limit in `ScriptLimits` inside the interpreter; the caller's timeout cannot stop a thread.
2. Route all filesystem access through the provided `ScriptFileSystem` — never touch `Workspace` directly.
3. Never expose network, process spawning, or direct writes.

## Tests

```sh
swift test --package-path Packages/PokeetCore      # tool wiring, overlay, proposals, limits
swift test --package-path Packages/PokeetScripting # engine: deadline, OOM, escapes, require, exit codes
```

Notable cases: infinite loop interrupted at the deadline, allocation bomb stopped at the heap limit, path escapes rejected, writes never reach disk before approval, proposals dropped for interrupted runs.
